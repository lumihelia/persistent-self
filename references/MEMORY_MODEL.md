# Persistent Self v3 — Memory Model

This reference defines the governance model behind `SKILL.md`.

## 1. Scope before storage

Every durable item belongs to one of three scopes:

### Global
Information that remains useful across projects: confirmed procedures, stable preferences/facts, cross-project priorities, and long-running threads.

### Project
Information whose meaning depends on a specific project: implementation state, project decisions, next actions, sources, rejected ideas, and local collaboration constraints.

### Session-only
Temporary information that should disappear with the current conversation unless later promoted deliberately.

Default to the narrowest scope that preserves usefulness.

## 2. Evidence state

### Confirmed
Supported by one of:

- an explicit user statement;
- an explicit user correction or approval;
- a durable user decision;
- a canonical project artifact within project scope.

### Candidate
Generated by agent interpretation or repeated observation without explicit confirmation.

Candidates can be useful for review, but they must not silently drive durable personalization as if they were facts.

### Superseded
An older confirmed entry replaced by newer confirmed information.

### Archived
Inactive history worth retaining.

## 3. Provenance

Keep provenance lightweight. Useful source labels include:

- `user-explicit`
- `user-correction`
- `user-decision`
- `artifact:<path>`
- `agent-observation`
- `migration:<source>`

A date plus a source label is often enough. Add a file path or short note when exact recovery matters.

## 4. Conflict handling

When two active entries conflict:

1. Prefer newer confirmed evidence over older confirmed evidence when the user has clearly changed position or a canonical artifact has changed.
2. Prefer confirmed evidence over candidates.
3. Do not preserve both conflicting claims as current truth.
4. Mark the older entry superseded or archive it only when historical context is useful.
5. If the conflict cannot be resolved from available evidence, surface it instead of guessing.

## 5. Promotion and demotion

Candidate → confirmed requires explicit user confirmation or authoritative artifact evidence appropriate to the scope.

Confirmed → superseded happens when newer confirmed evidence replaces it.

Confirmed/candidate → deleted happens when the user asks to forget/delete the information.

Age alone does not change evidence state.

## 6. Privacy

- Global personal memory should default to a private local or private-account location.
- Public repositories should contain templates, not live personal memory.
- Do not infer or store sensitive personal attributes as candidate observations.
- Store secrets, credentials, tokens, private keys, and authentication material outside memory files.
- If a host can expose memory to other agents or users, sharing permission is a separate decision from confirmation. Confirmed does not imply shareable.

## 7. Boot digest vs canonical source

A boot digest exists for low-cost startup. It should contain only the minimum context needed to locate and interpret deeper state.

For project context:

- `memory.md` = boot digest;
- `.context/` = canonical source.

For global memory:

- `memory/INDEX.md` = lightweight index;
- individual modules = canonical entries.

When a digest conflicts with a canonical file, update the digest after resolving from the canonical source.

## 8. Write quality

Durable memory should be:

- specific enough to change future behavior or retrieval;
- narrow enough to avoid overgeneralization;
- source-marked;
- easy to revise;
- easy to delete;
- free of duplicated current truth.

A large memory store is not inherently better. The goal is accurate continuity with controlled context cost.
