# Context quality and retrieval cost

Use when a long-lived project accumulates difficult-to-find knowledge or excessive startup reading.

Stored volume and loaded volume are separate. Preserve useful evidence outside active context; retrieve only what affects the current task. There is no universal token budget or file count that guarantees good recovery.

## Keep discovery small

- Root INDEX entries describe purpose, when to read, status/freshness where material, and location. Avoid copying detailed state into the index.
- If the root becomes hard to navigate, route to domain sub-indexes and then source sections. Add hierarchy only when it reduces real search cost.
- Keep semantic headings and stable source identifiers. Use targeted lexical search and read relevant sections before opening whole large documents.
- Replace stale current state; consolidate duplicates; retain historical sources off the default read path. Do not repeatedly summarize summaries and lose their evidence.
- Keep task tracking in its existing system. A second to-do list and handoff diary create maintenance and retrieval cost.
- Every retrieval expansion should answer a named gap. Stop when the next action is grounded. Avoid ritual reads of unrelated memory or all skill references.

Compression must preserve target, constraints, decision rationale, uncertainty, and verification boundaries when they affect future action. “Done” saves tokens but may erase the distinction between locally tested and deployed. Use pointers for detailed evidence.

## Measure quality together with cost

On representative fresh-session tasks record:

- whether critical decisions and constraints were recovered;
- whether the correct workstream was selected and stale claims revalidated;
- unnecessary repeat questions and repeated investigation;
- files/sections read, retrieval expansions, latency, and input tokens if the host exposes them;
- unrelated sources loaded or privacy boundaries crossed.

Compare on the same fixtures, model/host settings, access, and task. Report run count and failures. Byte/character counts are proxies for reading volume, not measured model tokens. Do not trade correctness for an arbitrary token ceiling or claim savings from shorter files alone.

## When to consider stronger retrieval

A large corpus alone is insufficient. Revisit the file-native design when repeated real failures survive simpler repairs: missed indexed decisions, vocabulary mismatch, large indexes, many irrelevant reads, fragmented authorized sources, or behavioral eval failures.

Try clearer filenames/headings, better routing, source maps, deduplication, stable tags, and a lightweight generated metadata index first. Index generation does not expand access permission.

If those fail, a possible incremental shape is canonical sources → metadata/provenance index → lexical and semantic candidate retrieval → scope/freshness filtering → small evidence set. Retrieved results remain evidence and pointers, not a shadow source of truth. Searchable does not mean authorized or current.

Persistent retrieval services may introduce cost, privacy, and operational commitments. Investigate within scope; obtain authority before crossing those boundaries. This protocol ships no vector store, retrieval service, or automatic consolidation job.
