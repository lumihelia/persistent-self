# Workstream checkpoint

Use this only if the existing issue/PR/task does not already carry the required state. It is volatile: revalidate on use. Replace stale state rather than accumulating a diary.

## Identity

- Workstream / owning task:
- Branch / PR / revision or workspace reference, where relevant and safe to store:
- Last refreshed:

## Target and accepted constraints

Link to the decisions and invariants that affect continuation.

## Current position

Distinguish completed and unfinished surfaces. State uncertainty explicitly.

## Evidence obtained

Identify checks, supporting results, revision/environment, and what each result proves. Local tests do not prove deployment or live behavior.

## Remaining work and blockers

Include unexecuted verification and pending authority decisions. Use existing task links instead of a duplicate backlog.

## Next meaningful checkpoint

What outcome can the next session pursue, and where should it begin?

## Sources needed to continue

Point to exact files/sections/records. Preserve rationale and evidence access boundaries. Do not embed raw transcripts or tool logs.
