## Project continuity

Use existing project sources and `.context/INDEX.md`, if present, as a routing map. Start with the current task, applicable instructions, and enough live evidence to act; retrieve deeper context only when relevant. Do not preload every linked file or require personal/global memory for project-only work.

When continuing after a gap, locate the matching workstream checkpoint through the index, optional `memory.md`, or existing issue/PR. Recover the goal, accepted constraints, unfinished work, evidence, and next checkpoint. Revalidate volatile claims. Search for specific missing information within authorized project scope and stop when the next action is grounded. State unrecoverable material gaps instead of inventing history.

Accepted project decisions govern desired behavior; live repository/runtime evidence establishes current behavior. A checkpoint or canonical filename is not proof of current reality. Preserve candidate/confirmed/observed distinctions and relevant provenance.

Within the adopted project maintenance policy and host permissions, preserve load-bearing decisions, corrections, constraints, blockers, and handoff state at meaningful boundaries. Read existing records before writing, reconcile stale claims, and update routing only when useful. Prefer links to existing authoritative docs over duplicated summaries. Do not keep a transcript diary or write after every turn.

Keep parallel workstream state with its owning task/branch/PR or scoped checkpoint. Preserve unrelated work and do not promote branch-only results to shared or deployed truth. Do not automatically promote project information to personal/global memory. Persistence does not authorize publishing, deployment, private-data disclosure, or broader data access.
